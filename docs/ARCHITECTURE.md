# Architecture

The native phone-only Manager is separate from the Android lab and locked messenger. It embeds a verified original sample APK, prepares it privately and requests normal PackageInstaller approval. Persisted session records recover foreground approval and installed-package state. Discord attachment remains unavailable in this Manager.

The opt-in Manager updater uses a fixed HTTPS GitHub feed and scoped release URLs. It validates version, minimum SDK, bounded size, SHA-256, package and the installed Manager's signing certificate before requesting native approval. Its sessions and cancellation state are separate from sample setup. Only controlled QA builds trust a domain-scoped localhost test CA; production has no feed override. See android/manager/README.md and MANAGER_PLAN.md.

The new API 1 PluginRuntime in src/plugins owns manifest validation, registry, dependency ordering, conflicts, host capability gates, settings, asynchronous start cancellation/timeouts, per-cleanup deadlines and reversed resource cleanup. Settings changes restart affected dependents; partial starts roll back. Diagnostics are bounded. Reviewed original modules run locally; declared capabilities are not an arbitrary-code sandbox.

The legacy three-feature FeatureRuntime remains unchanged for the locked Copperlight preview. Its persistence and presentation are independent of plugin settings.

The Chromium adapter uses a statically declared isolated-world content script on https://discord.com/channels/* only. It installs style elements; it does not hook Discord's private JavaScript runtime. The extension popup writes a single namespaced local settings record. The content adapter listens for changes and reconciles enabled features. Safe mode runs no features.

Pinned esbuild bundles current isolated content/popup entries and a DSIPlugins IIFE for controlled hosts. The extension ships no external npm runtime dependency, remote code, telemetry or upstream updater. Twelve built-ins are disabled by default. The v2 chrome.storage.local record migrates the three legacy choices; safe mode preserves them. DOM tooltip plugins restore owned titles, observe URL/date changes and release detached nodes.

Windows uses Electron 44.5.1 with sandboxed/context-isolated local windows and guarded IPC. An explicitly opened official Discord web window has no Node/preload and receives reviewed display modules in an isolated world. Its dedicated session gates device approval to the exact official main frame, revokes pending approvals on document navigation and confirms external HTTPS links in the system browser. Host states expose loading, readiness, errors, closure and reload/retry without account contents. Screen capture is denied: media prepermission also authorizes a legacy direct-capture path that bypasses a source chooser. Offline fixture and packaged executable smoke establish the adapter. The user subsequently confirmed live message delivery and voice audio in installed v0.4.0-dev.1; camera has an unsupported-browser gate and comprehensive live parity/installed-Discord injection remain unverified.

Browser Inspect includes fixed-key DOM existence observations on exact official channel routes, without reading text, identifiers or private URLs. All effects and live parity remain unverified. Context-dependent missing targets are reported rather than interpreted as failures. LIVE_INTEGRATION_PLAN.md owns ordered real-client work and the per-platform acceptance ledger.

The official Discord host window now removes the known Electron/DSI shell product tokens from its runtime user agent using window-scoped setUserAgent. Actual Chromium version, OS and engine identity are retained; the session default and other windows are unchanged. This addresses a browser-identification hypothesis raised by the user's unsupported-browser camera modal. It adds no native Discord bridge or private runtime hook and changes no permissions/capture gate. Controlled camera/WebRTC acceptance is separate from the pending live Discord camera retest.

Windows installs reviewed built-in CSS with documented webContents.insertCSS (author origin), avoiding inline-style CSP rejection without disabling page policy. It serializes per-window attachment and removes each host-owned key before replacement or Safe mode. DOM plugins remain in the unprivileged isolated runtime. Semantic-main and message-row media selectors match current visible markup. Runtime status reports startup results and absent targets; visual live effects remain an acceptance step. Numeric setting edits enable their owning plugin. The Copperlight launcher provides a deliberate fixed-URL default-browser handoff for supported browser screen sharing, with separate login and no automated call or capture.

The workbench confines filesystem/compiler/bundler operations to a selected project (plus pinned TypeScript standard libraries), validates symlinks/revision hashes, rejects multiply-linked files and Windows alternate streams, and exports checksummed development packages. These checks are not an OS boundary against concurrent local filesystem mutation. Node tests run as the user after an explicit action.

Controlled previews use an opaque in-memory document, restrictive CSP, no Node/preload privileges and a dedicated ephemeral session denying file/network requests, permissions and downloads. A scoped WebRTC policy plus host-owned rejecting proxy blocks the tested STUN/UDP and TURN/TCP paths. Preview destruction settles pending startup so Stop recovers the editor after synchronous hangs. These guards are defense in depth, not an arbitrary-code OS sandbox; see SECURITY_REVIEW.md.

Android uses a separate native Java API 1 engine and three reviewed native-view handlers. The development lab has no network permission. A local non-root patcher preserves a selected monolithic APK, adds an original Application bootstrap and separate DEX, and writes a development-signed output/integrity report. Browser CSS does not run on Android. Actual Discord attachment/private runtime discovery remains unverified.

The GitHub Pages preview reuses the actual feature runtime and CSS against sample messages. Preview settings use a separate browser localStorage record. Pages hosts a ZIP built from the same original extension sources; no GitHub login is needed to download it. The deployment workflow builds and verifies before publishing.

The messenger preview keeps contact data and per-conversation histories in a small original model. Messages stay in tab memory, and rendering uses textContent for message bodies. No network adapter is connected. The Copperlight layout belongs to the preview; applying that shell to Discord remains separate platform work.

The preview's theme selector is independent of feature lifecycle. Its complete CSS themes cover the entire messenger and preferences. It shares Compact messages and Reduced motion with the extension, but does not install Discord's Signal CSS, which would override light surfaces. The preview settings record stores a validated theme alongside normalized feature settings; older Signal selections migrate to High contrast. Discord/Relay/Local buttons display preview-only connection status and make no network requests.

The rebuilt preview owns a saved signal Play/Pause setting and explicit system-motion override. By default, reduced-motion preferences stop the decorative equalizers. Clicking Play clears the preview Reduced motion feature choice and opts the equalizers into motion under a system preference only when that preference is currently active. Other page animations still obey the system setting. Meter height/animation is CSS only, not audio input, network health or real connection activity.

The workspace-tools module owns four native modal surfaces: a searchable archive of the active in-tab conversation, a contact card, local profile editing and a cursor-aware emoji picker. All user/message text is rendered with textContent. Conversation export generates a local text Blob; it performs no upload. Profile name/note use the separate validated localStorage record dsiChat.localProfile.v1. A renamed profile changes future message authors; historical authors remain unchanged. This is local display personalization, not an account or authentication system. Native modal dismissal returns focus to the opener, or to the composer after an explicit compose/emoji action. On desktop displays at least 1000px wide and 640px high, window height follows the viewport, and contact/message areas scroll internally.

Contact organization uses the validated dsiChat.contactBook.v1 localStorage record, separate from appearance and profile. contact-book.mjs owns local group names, membership and favorites; contact-tools.mjs renders the list and native action/group dialogs. Search matches names, status notes and local group names, including collapsed groups. Favorites filter the existing list without duplicating contacts. Custom group removal reassigns members to the first default group and retains favorites; messages, tabs and drafts are untouched. Two default groups can be renamed but not removed. Storage failure leaves changes usable for the visit and reports the limit through a status region. Contact actions return focus to their row, or to search if filtering removes it. Write a message returns focus to the composer. Group collapse is session-only; transient search/favorite filters reset on reload.

Copperlight adds a final theme/composition stylesheet, functional navigation rail, responsive contact/station sidebar and original decorative valley banner. The sidebar is updated from the same active-contact model as the header. Shortcut modals return focus to the actual initiating button. New visitors and appearance reset use day/Afternoon; existing valid day/dark/contrast values retain their choices. No network or persistence model changes accompany the redesign.

The single decorative signal meter and existing saved Play/Pause now live in the station sidebar. Header animation is removed without changing motion preferences/storage. An original SVG symbol sprite decorates existing controls, remains aria-hidden, and leaves names/actions intact.

## Authorized growth direction

The user confirmed original DSI code combining capabilities and ideas from Vencord, Equicord, Vendetta and Revenge. Those engines/plugins remain behavior references, not runtime dependencies. IMPLEMENTATION_PLAN.md records the delivered versioned plugin contract, registry/lifecycle, dependency/conflict checks, scoped cleanup and platform adapters. Browser/Windows share JavaScript logic; Android implements native host operations separately. Further native host discovery and reference capability expansion remain planned. Copperlight presentation and existing persistence scopes stay locked. Tools and shipped Windows dependencies are recorded in TOOLCHAIN.md and PROVENANCE.md.
